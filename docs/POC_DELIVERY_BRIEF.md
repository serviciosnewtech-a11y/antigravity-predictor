# Antigravity Predictor — Proof of Concept
## Delivery Brief

**Date:** 2026-07-27
**Status:** PoC operational, advisory mode
**Prepared for:** client review

---

## 1. What was built

An end-to-end cryptocurrency futures signal system, running live against Bybit linear
perpetuals (BTC/USDT, ETH/USDT, SOL/USDT) on a 15-minute timeframe.

| Component | Status |
|---|---|
| Live market data ingestion (REST + WebSocket) | Operational |
| 65-feature engineering pipeline | Operational, 65/65 parity verified live |
| Feature integrity gate (fail-loud) | Operational |
| LightGBM inference engine, 6 models | Operational |
| Signal dashboard (web) | Operational |
| Execution layer | Operational, DRY_RUN / paper mode |
| Reproducible evaluation harness | Operational |
| Deployment preflight gate | Operational |

The system ingests live candles, computes the full feature vector each tick, runs
inference, and publishes directional signals with ATR-derived entry, stop and target
levels — continuously, without manual intervention.

## 2. Engineering safeguards

Three safeguards were built into the platform, each in response to a specific
class of failure that silently corrupts trading systems.

**Feature integrity gate.** Missing or non-finite features are never silently replaced with
zeros. Inference is blocked and the system reports `UNAVAILABLE` rather than scoring a
degraded input. Feature health is visible per subsystem, so a degraded data feed is
identifiable at a glance rather than surfacing as inexplicably poor signals weeks later.

**Reproducible evaluation harness.** Every performance figure the system produces is
generated by a committed script into a committed report, referenced by file path and
dataset checksum. No performance claim exists as an unverifiable assertion. Any result can
be regenerated byte-for-byte on demand.

**Deployment preflight.** Deployment readiness is established by a script that inspects the
target machine and emits an evidence file, rather than by judgment. Twelve historical
failure modes are checked explicitly before any deployment proceeds.

## 3. Measured baseline

The directional model was evaluated out-of-sample on two years of 15-minute data
(70,078 bars, 2024-07-19 to 2026-07-19), using a chronological 70:30 split with an embargo
gap to prevent label leakage across the boundary.

| Asset | Out-of-sample AUC | Directional accuracy at high confidence |
|---|---|---|
| BTC/USDT | 0.5325 | 60.3% |
| ETH/USDT | 0.5291 | 56.9% |
| SOL/USDT | 0.5168 | 55.7% |

**The directional signal is statistically real.** BTC's AUC sits approximately 6–7 standard
errors above chance on ~21,000 out-of-sample bars. It survived two independent validity
controls: a label-shuffle null test (AUC 0.5037, confirming no harness leakage) and a
feature-ablation sentinel.

**At 15 minutes, the signal does not yet exceed transaction costs.** Gross expectancy at
mid-range confidence runs +0.002% to +0.02% per trade against a round-trip taker fee of
0.11%. The edge is genuine; the current horizon is too short for it to clear the fee.

This is the expected position for a system at PoC stage, and it is a measured, reproducible
starting point rather than an estimate.

## 4. Validation finding

During evaluation, the harness identified a lookahead defect in the higher-timeframe feature
merge: 1-hour and 4-hour context features were being aligned to 15-minute bars by bar *open*
time, allowing up to 45 minutes of future price information into the training set.

Uncorrected, this inflated apparent model performance from AUC 0.53 to 0.71 — a result that
would have looked highly profitable in backtest and failed immediately in live trading.

The defect was identified, corrected, and the correction independently verified by an
ablation sentinel before any capital or paper-trading decision was made. All affected
figures were retracted and regenerated.

**This is the safeguard architecture working as designed.** The class of failure it caught is
the single most common cause of trading systems that perform well in backtest and lose money
live.

## 5. Tuning roadmap

The system is a platform for iteration, and the baseline above defines where iteration
starts.

**Immediate — horizon extension.** Transaction cost is fixed per round trip, while the
signal's expected move scales with the horizon's volatility. Clearing the 0.11% fee requires
roughly 5–10× the current gross expectancy, which corresponds to a 2–4 hour horizon rather
than 30 minutes. The evaluation harness runs this as a configuration change — results in
hours, not weeks.

**Near term — feature development.** The current 65-feature set is inherited from an earlier
architecture. Higher-timeframe context, now that it is correctly aligned, contributes
approximately nothing and should be replaced. Order-book microstructure and funding-rate
dynamics are the strongest untested candidates.

**Near term — execution economics.** Maker execution reduces round-trip cost from
approximately 11 bps to 4 bps. This materially changes the profitability threshold, at the
cost of fill uncertainty and adverse selection, both of which are quantifiable in paper
mode.

**Gating — paper trading.** A six-condition unfreeze gate governs progression from advisory
to live execution, requiring sustained out-of-sample performance, calibration monotonicity,
and regime stability before any capital is committed.

## 6. Current status

The system is deployed and operational in **advisory mode**. It publishes signals
continuously and commits no capital. Paper-trading validation is the next milestone, and the
horizon-extension test is the immediate next experiment.

Every figure in this brief traces to a committed report file and a dataset checksum, and can
be independently regenerated on request.
